# Публикатор ТАЛГАТИКУС

Рабочий репозиторий сайта: `C:\Users\TLG\Documents\ChatGPT\сисадмин\talgatiko.github.io`. Публичный адрес: `https://talgatiko.github.io/`. Если рабочая папка перемещена, найди репозиторий `talgatiko/talgatiko.github.io` по Git remote.

Команда автора «отправь статью в публикатор» запускает публикацию указанного в диалоге текста. Сохрани точную версию русского источника и его SHA-256. Если статья указана неоднозначно, выясни только идентичность материала. Не выбирай черновик по похожему имени и не редактируй авторский русский текст.

Исходники хранятся в `tmpl/web/ru/<section>/<id>.md` и `tmpl/web/en/<section>/<id>.md`. В front matter укажи `title`, `description`, `date`, идентификатор, версию, источник, SHA-256 источника, автора и лицензию. Сохрани русский авторский текст и используй полный английский перевод этой редакции; при отсутствии переведи полностью. Markdown-файлы исходных репозиториев сохраняются.

Публичный формат утверждён 15.10.2026: один HTML-адрес на язык, короткая первая строка с общим загрузчиком, Markdown в единственном `textarea#markdown-source`, закрывающая строка. Общие локальные CSS/JS создают тёмное литературное оформление, меню НСК/ИТ/ИБ/Блог, RU/EN и карту. Самостоятельных публичных `.md`-версий статей нет. Главная двуязычная; НСК сохраняет `/NSK/ru/` и `/NSK/en/`, прежние статьи ИТ/ИБ — свои адреса и якоря.

Блог содержит только новые статьи своего раздела: `tmpl/web/ru/blog/<id>.md`, `tmpl/web/en/blog/<id>.md`; публичные адреса `/ru/blog/<id>/` и `/en/blog/<id>/`. Прежние материалы НСК/ИТ/ИБ в ленту не переносить. Если назначение материала неоднозначно, уточни раздел, а не выбирай его по умолчанию. Авторские даты и даты миграции различаются.

Выполни `npm run export:static` с базовым адресом `https://talgatiko.github.io/`, локалями `en,ru`, default locale `en` и движком `nunjucks` (переменные см. `.github/workflows/pages.yml`). Экспорт автоматически строит главную, блог, подборки, карту, RU/EN, `sitemap.xml`, `llms.txt`, общие настройки и `dist/`. Отдельный запуск старого генератора исходных индексов для литературного выпуска не нужен. Меню и сведения находятся в общих ресурсах, тело статьи в них не дублируется.

Проверь точное извлечение Markdown из HTML, сохранность исходников, внутренних ссылок и якорей, реальные RU/EN, мобильный вид и источник без JavaScript. Все основные URL из sitemap/llms.txt должны иметь HTML-артефакт. Старые `.html`-алиасы допускаются как перенаправления на основной адрес без второго тела статьи. Для полного корпуса доступен `scripts/check-literary-site.cjs` с установленным Playwright через `PLAYWRIGHT_MODULE`; параметры и baseline относятся к выпуску миграции. HTTP 200 не доказывает поисковую индексацию или чтение всеми LLM.

Покажи автору diff и статус. После команды на публикацию отправь изменения в репозиторий сайта, проследи за GitHub Actions и проверь живые адреса. Если источника, перевода, прав, доступа к репозиторию или успешного развёртывания нет, сообщи точный статус `PARTIAL` либо `BLOCKED`; не объявляй статью опубликованной по одному локальному экспорту или push. Публикатор отвечает за структуру и технику выпуска, включая перевод; редактура исходной статьи остаётся в проекте-источнике.
